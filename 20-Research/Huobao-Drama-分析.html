三、核心管线架构（11步工作流）

┌──────────────────────────────────────────────────────────────────┐
│  第1步: 剧本输入 (Script Input)                                    │
│  - 手动输入/粘贴小说文本到剧集                                       │
├──────────────────────────────────────────────────────────────────┤
│  第2步: 剧本改写 (Script Rewriting)                                │
│  Agent: script_rewriter                                          │
│  输入: 原始小说文本 → 输出: 格式化剧本 (场景头+动作+对白)              │
│  格式: ## S01 | 内景 · 地点 | 时间段                                │
├──────────────────────────────────────────────────────────────────┤
│  第3步: 角色提取 (Character Extraction)                            │
│  Agent: extractor                                                │
│  自动提取角色名/外貌/性格，智能去重（同名合并）                         │
├──────────────────────────────────────────────────────────────────┤
│  第4步: 场景提取 (Scene Extraction)                                │
│  Agent: extractor                                                │
│  提取地点/时间/氛围，去重规则: 地点+时间段精确匹配                      │
├──────────────────────────────────────────────────────────────────┤
│  第5步: 角色图片生成 (Character Image Gen)                          │
│  Agent: grid_prompt_generator (角色模式)                           │
│  为每个角色生成英文提示词 → AI文生图 → 角色定妆照                       │
├──────────────────────────────────────────────────────────────────┤
│  第6步: 场景图片生成 (Scene Image Gen)                              │
│  Agent: grid_prompt_generator (场景模式)                           │
│  为每个场景生成英文提示词 → AI文生图 → 场景背景图                       │
├──────────────────────────────────────────────────────────────────┤
│  第7步: 分镜拆解 (Storyboard Breakdown)                            │
│  Agent: storyboard_breaker                                       │
│  剧本 → 镜头序列，每个镜头10-15秒                                    │
│  填充15个字段: title/shot_type/angle/movement/action/              │
│  dialogue/video_prompt/image_prompt/bgm/sound_effect...           │
│  视频提示词格式: <location>/<role>/<voice>/<n> 标记                  │
├──────────────────────────────────────────────────────────────────┤
│  第8步: 视频生成 (Video Generation)                                │
│  分镜图 → 图生视频 (支持3种参考模式)                                 │
│  - single: 单图参考                                               │
│  - first_last: 首尾帧过渡                                          │
│  - multiple: 多参考图                                              │
│  异步轮询(300次×10s) 或 Webhook回调(Vidu)                          │
├──────────────────────────────────────────────────────────────────┤
│  第9步: TTS配音 (Voice Generation)                                 │
│  对白解析 → 角色音色匹配 → MiniMax TTS → 音频文件                     │
├──────────────────────────────────────────────────────────────────┤
│  第10步: 单镜头合成 (Storyboard Compose)                            │
│  FFmpeg: 视频 + TTS音频 + SRT字幕烧录 → 合成MP4                       │
│  libx264/AAC编码, CRF 23                                          │
├──────────────────────────────────────────────────────────────────┤
│  第11步: 整集导出 (Episode Merge)                                   │
│  FFmpeg: 全部镜头按序拼接 → 完整剧集MP4                               │
└──────────────────────────────────────────────────────────────────┘

3.1 宫格图特色流程

Huobao Drama 有一个独特的”宫格图”机制：

  1. 宫格图生成: AI生成一张包含多个格子的大图 (rows × cols)
  2. 宫格图切分 (Sharp): 精确切割成独立的小图，分配给不同镜头
  3. 三种宫格模式:
    • first_frame: 首帧风格宫格（统一风格多镜头）
    • first_last: 首尾帧节奏感宫格
    • multi_ref: 同一镜头多角度宫格

这是生产流水线的关键优化——一次API调用生成多个分镜的首帧图，降低成本。

四、Mastra Agent 体系

4.1 Agent架构

Mastra Agent Factory (动态创建)
└── 每次请求根据 agent_configs 表配置 + SKILL.md 注入
    ├── Model: 统一使用 text service 的 OpenAI-compatible provider
    ├── Instructions: DB配置 > SKILL.md扩展 > 默认prompt
    └── Tools: 每个Agent有专用工具集（闭包注入 episodeId/dramaId）

4.2 五个Agent详解

Agent职责工具数关键能力
script_rewriter小说→格式化剧本read/save格式转换，对话驱动
extractor角色+场景提取去重read/save×2同名合并，地点+时间段匹配
storyboard_breaker剧本→分镜序列read/save/update15字段完整填充，视频提示词
voice_assigner角色→音色分配list/get/assign性别/性格匹配
grid_prompt_generator提示词工程read/generate角色/场景/宫格三模式

4.3 可扩展性

  • skills/ 目录下每个Agent有 SKILL.md 文件
  • 后端 skills.ts 实现动态加载：loadAgentSkills(type) 读取并注入到instructions
  • Agent配置存储在数据库 agent_configs 表中，可运行时修改prompt/model/temperature
  • 新增Agent需: ① 创建tools文件 ② 注册到 DEFAULT_PROMPTS ③ 创建SKILL.md

七、关键判断

7.1 玩具还是生产工具？

结论：介于”演示级工具”和”半自动生产工具”之间。

生产工具的特征：

  • ✅ 完整的Docker部署方案，开箱即用
  • ✅ 商业版已上线运营 (drama.chatfire.site)
  • ✅ 完善的API抽象层，多厂商适配
  • ✅ 数据库持久化，任务状态追踪
  • ✅ FFmpeg专业视频处理管线
  • ✅ Webhook回调支持异步长任务

玩具/演示的特征：

  • ⚠️ AI视频质量受限于底层模型（Seedance/MiniMax生成质量参差不齐）
  • ⚠️ 缺乏协作/团队功能
  • ⚠️ 无视频审核/人工干预机制（只能重新生成）
  • ⚠️ 单集生成而非项目管理工具
  • ⚠️ 核心4300行单文件组件，代码组织可优化
  • ⚠️ 许可限制商业用途（需购买商业版）
  • ⚠️ 无测试代码，质量保障不足

综合：这是一个可用的”AI短剧半自动生产平台”，对个人创作者和小型工作室有实用价值，但难以支撑工业化生产。

7.2 技术壁垒分析

壁垒强度说明

Seedance集成★★☆☆☆使用公开API，无独家合作

核心壁垒总结： Huobao Drama的真正壁垒不在单一技术点，而在于对短剧制作领域的深入理解 → 11步流程设计、角色管理体系、分镜规范、宫格图优化等，这些是领域知识壁垒而非纯技术壁垒。

7.3 威胁评估

对Jellyfish/我们产品的威胁等级：★★★☆☆ (中等)

直接威胁：

  • 同一赛道（AI视频生产工具），目标用户重叠
  • 社区增长迅速（半年12K+ stars）
  • 中文市场先发优势明显
  • 开源+商业版双轨策略成熟

可防御点：

  • 许可限制（CC BY-NC-SA）阻止了无许可的商业化使用
  • 短剧垂直定位既是优势也是局限 — 无法覆盖通用视频制作场景
  • 依赖外部AI API，供应商锁定风险
  • 代码质量/测试/架构有提升空间
  • 无团队协作功能，不易扩展为企业级

八、战略启示

  1. “一句话生成”的魔力 — Huobao Drama的核心卖点是极低的输入门槛。输入一部小说就能生成完整短剧，这个”从0到1”的体验远超竞品

  2. 管路化 vs 灵活化 — Huobao选择了刚性11步管线，降低了用户决策成本；Jellyfish需要权衡灵活性和易用性

  3. 角色系统的战略价值 — 角色作为”跨集一致性”的锚点，是短剧质量的命门。Huobao将角色管理提升为一等公民的做法值得借鉴

  4. 成本优化创新 — 宫格图切分机制体现了对AI API成本的精打细算，这种优化思路应该应用到所有AI视频工具中

  5. 中文生态壁垒 — Huobao在中国市场（LINUX DO社区、百度云/阿里云集成、Seedance等国内模型）建立了生态系统，海外产品难以突破

  6. 开源商业模式 — CC BY-NC-SA + 商业版双轨策略非常有效，但许可证实际上阻止了大部分商业场景下的fork使用
