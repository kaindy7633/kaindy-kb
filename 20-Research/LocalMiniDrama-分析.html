二、核心功能完整分析

2.1 完整创作工作流 (8步骤)

故事梗概 → AI剧本生成 → 角色提取+形象图生成 → 场景提取+背景图生成 
→ 道具生成 → 分镜脚本拆解 → 逐镜图片/视频生成 → 视频合成导出

亮点:

  • 一键流水线：角色图→分镜图→视频→合成，全程自动
  • 智能补全：跳过已生成内容，只补缺失部分
  • 失败重试：每步最多重试3次，处理429限流
  • 并发生成：图片/视频各3路并发 (v1.1.15+)

2.2 Seedance 2.0 集成方式 (关键分析)

集成方式是云端API调用，非本地模型！

  • 通过火山引擎方舟 API 调用 doubao-seedance-2-0-260128 (Seedance 2.0 Pro)
  • 接口规范 volcengine_omni — 支持多参考图输入 (最多9张)
  • URL: POST {base}/contents/generations/tasks
  • 每张参考图带 role: reference_image 标签
  • 视频时长: Seedance 2.x 自动吸附到 4-15秒
  • 支持音色参考音频输入 (Seedance 2.x 独有)
  • 还支持 volcengine_omni 或 kling_omni 两种全能模式

Seedance 2.0 在 LocalMiniDrama 中的独特功能:

  • 分镜「全能模式」 (v1.2.5+)：经典分镜/全能模式一键切换
    • 全能模式中间为「片段描述」字段，支持 @图片1 @图片2 引用参考图
    • 有内容时不拼接下方结构化提示词，避免覆盖 @图片N 编排
    • 调用前自动校验配置是否匹配 (volcengine_omni + Seedance 2.x)
  • 尾帧衔接 (v1.2.7)：ffmpeg提取末帧设为下一镜首帧
  • 首帧尾帧分字段绑定 (v1.2.7)：不污染分镜主图

三、本地部署方案分析

3.1 硬件需求

组件最低要求说明
CPU任意现代x64 CPU前后端仅需 Node.js 运行
GPU无要求所有图片/视频生成通过云端API
RAM~2GB (Node.js + SQLite)轻量级后端
磁盘~500MB (软件本身) + 生成内容存储建议10GB以上
网络需要稳定公网连接调用各家AI API
OSWindows 10+ (exe) / macOS ARM64 (DMG)理论上 Linux 也可开发模式运行

3.2 安装流程

普通用户 (exe方式):

  1. 下载 ~195MB exe，双击运行
  2. 在「AI配置」页填入 API Key
  3. 开始创作

开发者 (源码方式):

⚠️ 配置文件在 %APPDATA%\LocalMiniDrama\backend\configs\config.yaml (exe模式)
⚠️ SQLite 数据库在 backend-node/data/drama_generator.db

3.3 RTX 3050 4GB 能跑吗？

结论：完全能跑，但GPU不是瓶颈。

LocalMiniDrama 是一个 编排调度层，所有AI生成（图片、视频）通过云端API完成。本机只需要运行：

  • Node.js Express 后端 (极低资源消耗)
  • Vue 3 Vite 开发服务器或 Electron 桌面壳
  • SQLite 本地数据库
  • ffmpeg (用于视频合成、尾帧提取，非AI推理)

RTX 3050 4GB 在本工具中几乎没有用武之地，除非：

  • 本地部署 Ollama 用于文本生成 (4GB VRAM 可跑 Qwen2.5:7B Q4)
  • 但图片/视频生成仍需云端 API

4.2 LocalMiniDrama 的核心差异化优势

  1. 纯本地+Seedance 2.0 全能模式：v1.2.5+ 是目前唯一已知的开源工具原生支持 Seedance 2.0 多图参考的
  2. 零部署门槛：Windows exe 双击即用，不需要 Docker/GPU/环境配置
  3. 全流程覆盖：从故事创意到成片合成，一个工具完成
  4. 精细分镜控制：全能模式 @图片N 引用体系+景别/运镜/灯光/景深参数

6.2 我们的应对策略

  1. 差异化定位：LocalMiniDrama 是「编排调度层」(全部云API)，我们可以做「本地推理层」(真正的本地模型生成)
  2. 超越Seedance 2.0：如果我们能集成 Seedance 2.0 + 更多本地开源模型，形成混合方案
  3. 多平台：LocalMiniDrama 以 Windows 为主，我们可以优先 Linux/Docker 和 Web 端
  4. TypeScript + 工程化：LocalMiniDrama 纯JS单人维护，我们可以在代码质量上超越
  5. 社区建设：他的170 fork说明需求巨大但缺少组织，我们可以建更好的社区

6.3 关键风险点

  • Seedance 2.0 API 费用：视频生成按秒计费，成本不可控。LocalMiniDrama 用户需自行承担API费用
  • 云端依赖：火山引擎 API 稳定性不可控，用户完全依赖第三方
  • 可持续性：单人开源项目，作者热情消退后可能停滞
  • 安全审计：exe打包的Electron应用存在安全审查风险

七、总结与建议

7.1 核心发现

  1. LocalMiniDrama 是「编排层」，不是「推理层」：所有AI生成通过云端API，本地只运行UI+数据库+ffmpeg
  2. Seedance 2.0 集成是最大亮点：volcengine_omni 协议 + 多图参考 + @图片N 体系设计精巧
  3. 增长迅猛但生态脆弱：4个月 652星 很快，但单人维护、纯JS、无商业模式
  4. 本地化部署不是真正的「本地AI」：只是数据存储本地，AI推理仍依赖云端
  5. v1.2.7 的尾帧衔接和分镜导出是实用功能：体现了作者对短剧工作流的深刻理解

7.2 可借鉴的核心设计

功能优先级说明
三模型独立配置 UIP0文本/图片/视频分开配置，用户友好
接口规范抽象 (omni协议)P0不同模型用不同协议但统一接口
全能模式 + @图片NP1高级用户灵活控制参考图
并发任务统一StoreP1异步任务管理+断点恢复
ffmpeg 尾帧/首帧衔接P2提升视频连贯性
jsonrepair 自动修复P2提升AI JSON成功率
工程导出/导入 ZIPP2项目迁移和分享

7.3 行动建议

  1. 短期 (1周内)：用 exe 实际跑通 LocalMiniDrama + Seedance 2.0 全流程，体验真实瓶颈
  2. 中期 (1月内)：吸收其「全能模式」设计思路，设计我们的多模型编排方案
  3. 长期：如果我们做本地推理，与之形成互补而非直接竞争
