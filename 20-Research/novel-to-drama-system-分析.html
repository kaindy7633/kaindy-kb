2.1 实现原理

2.2 设计亮点

  1. 零重启: 编辑 prompts/*.py 文件后，下一次 API 调用自动使用新版本
  2. mtime 检测: 用文件修改时间戳做缓存失效，O(1) 判断
  3. importlib.reload: Python 标准库，无需额外依赖
  4. 单例模式: 模块级 _loader，全局共享一个缓存
  5. 薄封装层: prompt_builder.py 只做参数转发，所有 prompt 逻辑在 prompts/*.py

2.3 对Jellyfish的借鉴价值

三、分层上下文注入 🔥

3.1 三层漏斗模型

该系统的上下文注入严格按层级递进，从宏观到微观：

Layer 1: 分卷大纲 (volume_prompt.py)
  注入内容:
  ├── 故事梗概 (blurb, 全项目共享)
  ├── 世界观 (2000字截断)
  ├── 角色体系 (全部角色)
  ├── 故事线
  ├── 已有分卷 (情绪弧线+卷尾钩子, 防止重复)
  ├── 近期正文回顾 (recent_context)
  └── 生成规则 (卷数限制、章范围、平台口味)

Layer 2: 章节细纲 (xigang_prompt.py)
  注入内容:
  ├── 故事梗概 (全项目共享)
  ├── 世界观 (2000字)
  ├── 角色速查 (含首登场章号)
  ├── 故事线 (主线至少3章出现一次)
  ├── 本卷规划 (vol_theme + core_events + emotion_arc) ← 卷级上下文
  ├── 已有细纲 (最近5章, 含爽点/情绪/钩子, 防止重复) ← 增量上下文
  ├── 近期正文回顾 (recent_context) ← 正文级上下文
  └── 生成规则 (爽点池、钩子池、故事线选择)

Layer 3: 章节写作 (write_prompt.py)
  注入内容:
  ├── 故事梗概 (共享)
  ├── 世界观 (3000字)  ← 比细纲更多
  ├── 角色身份速查 (含已故标记、首登场章号) ← 角色约束
  ├── 风格规则 (禁用词/句式/对话/描写/视角/章节起结尾) ← 门禁注入
  ├── 前情提要 (已发生事件, 指定不要重复)
  ├── 近期正文回顾 (标题+爽点/情绪/钩子+出场角色+结尾场景) ← 避免矛盾
  ├── 本章PRD (概要/爽点/钩子/情绪/冲突) ← 本章指令
  ├── 下一章预告 (绝对禁止抢跑) ← 防幻觉
  └── 写前注入 (字数门禁+角色白名单+口语色板+衔接要求) ← 最终约束

4.1 是什么

4.2 工作原理

存储: Character 模型 → speech_pattern Text 字段 → JSON 字符串

注入 prompt: common.py → build_voice_rules(characters) 函数

注入位置: write_prompt.py 第八节「写前注入」第6条

6. 对话遮名能辨人。{voice_rules}

输出效果（prompt中）：

6. 对话遮名能辨人。宋砚：短句为主，不超过15字；特征：话尾带'呢'/'嘛'，从不直接表达愤怒；节奏：慢半拍；例句："这事儿啊...没那么简单。" 沈知行：长句为主，逻辑严密；特征：反问句多，压迫感强；例句："你觉得你有资格跟我谈条件？"

4.3 设计亮点

  1. 遮名可辨人: 即使遮住角色名，读者/观众也能通过说话方式认出谁在说话
  2. 结构化JSON: 5维描述（句式+特征+节奏+例句+口癖），AI容易理解和执行
  3. 与角色体系绑定: 用户在创建角色时填写，写入数据库，prompt自动注入
  4. 热加载兼容: 修改角色 speech_pattern → 下次写章自动生效（无需重启）

6.4 建议移植优先级

P0 (立即移植):
  ├── prompt热加载系统      → 解决Jellyfish改prompt需重启的问题
  └── 口语色板系统          → 提升分镜对白的一致性和辨识度

P1 (短期移植):
  ├── 字数控制器            → 用于分镜文本字数校验
  └── 硬门禁规则引擎        → 分镜生成时注入风格约束

P2 (中期移植):
  ├── 分层上下文注入        → 分镜生成时加入上游章节上下文
  └── QC质检规则            → 分镜生成后自动扫描违规

P3 (远期):
  └── 防抢跑机制            → 连续分镜生成时防止角色/场景跳跃

七、总结

核心价值

novel-to-drama-system 是一个小而精的生产级系统（仅 ~8K 行 Python），核心亮点：

  1. Prompt热加载: mtime+importlib.reload，零重启更新prompt，实现极致简单
  2. 分层上下文注入: 漏斗模型从宏观到微观，每层只注入该层需要的上下文，有效控制token消耗
  3. 口语色板系统: 角色说话方式的5维描述，遮名可辨人，解决AI对白”千篇一律”的顽疾
  4. 双层规则引擎: HardRules(注入约束) + ScanRules(扫描检测) + ai_scan.py(质检)，形成完整质量闭环
  5. 防抢跑机制: 通过”下一章预告”负面约束，解决AI写作中最常见的提前推进剧情问题

对Jellyfish的启示

  • Prompt管理方向: 热加载 → DB规则参数 + Python模板文件 混合方案
  • 上下文设计方向: 分镜/提取 prompt 应加入上游章节/镜头上下文
  • 质量管理方向: 规则注入(prompt约束) + 扫描检测(ai_scan) 双层体系
  • 角色一致性方向: 口语色板比视觉一致性更优先解决——剧本阶段就做好一致性
