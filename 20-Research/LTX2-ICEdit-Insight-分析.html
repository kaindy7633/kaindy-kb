二、核心技术架构

2.1 三大核心创新

TADA (Task-Aware Decoupled Adapter)

  • 替代传统单一 LoRA 的方案
  • 任务感知门控：根据任务类型（修复/高清/去水印/去字幕）自动激活不同的适配器分支
  • 分支解耦注入：将”结构恢复”和”纹理/语义编辑”分离为独立的注入通道
  • 弱正交约束：减轻共享骨干网络上的任务干扰

FGLC (Flow-Guided Latent Consistency)

  • 在潜空间实现时序一致性
  • 光流对齐：跨帧运动先验引导注意力偏置
  • 跨帧滑窗关联：相邻帧间建立关联，降低闪烁
  • 遮挡补全稳定性：运动区域和遮挡区域更自然的背景重建

PMTR (Progressive Multi-Task Routing)

  • 渐进式课程学习策略
  • 协同任务路由：单模型同时支持多任务
  • 提高联合训练的收敛稳定性和泛化表现

2.2 流水线架构

默认单阶段推理 (推荐，single_stage=True):

输入视频 → Video VAE Encoder → IC-LoRA引导(参考帧拼接到去噪序列)
→ Transformer扩散(融合LoRA权重) → Video VAE Decoder → 输出MP4

Sigma 序列: [1.0 → 0.9375 → 0.8125 → 0.5625 → 0.25 → 0.0]

两阶段推理 (—two-stage):

输入视频 → VAE Encoder @半分辨率 → Stage1扩散(IC-LoRA引导)
→ VideoUpsampler ×2 → Stage2精修(无IC-LoRA) → VAE Decoder → 输出MP4
  • Stage1 sigma: [1.0 → 0.9375 → 0.8125 → 0.5625 → 0.25 → 0.0]
  • Stage2 sigma: [0.85 → 0.7250 → 0.4219 → 0.0]

⚠️ 关键发现: 默认单阶段全分辨率，避免两阶段 Stage2 换脸/内容漂移。这是与其他 LTX 视频编辑方案的重要区别。

2.3 关键技术修复（FP8兼容）

  1. FP8 权重反量化：apply_loras 前将 fp8_input_scaled 反量化为 bf16，避免 LoRA delta 方向错误
  2. 一体化 checkpoint 兼容：VAE/Audio VAE/Vocoder 复用 SDK 内置 key filter，Gemma 使用 GEMMA_HF_TEXT_ONLY_KEY_OPS
  3. 自带 ltx_vendor SDK：无需外部 LTX-2/ 目录，通过 sys.path.insert(0, "ltx_vendor") 加载

优化建议

分辨率约束

  • 单阶段: height/width 必须是 32 的倍数
  • 两阶段: height/width 必须是 64 的倍数
  • 帧数: 8k + 1 (如 25/97/217)
  • 常见: 输入 270×480 → 输出 704×1184

六、ComfyUI 集成方案

关键发现: IC-LoRA 不依赖 Insight 一体化 checkpoint

IC-LoRA 权重可以直接挂载到 ComfyUI 中的 LTX-2.3 官方原生模型 上。仓库提供两个参考工作流：

工作流文件适用场景
LTX-2.3-ICLORA编辑-官方模型版本.json官方原生模型 + IC-LoRA
LTX-2.3-IC编辑-comfyui模型版本.jsonComfyUI 分离模型格式

ComfyUI 节点映射

ComfyUI 节点功能
LTXICLoRALoaderModelOnly加载 IC-LoRA (默认 strength=1.0)
LTXAddVideoICLoRAGuide通过 reference latent 注入 IC-LoRA 引导
SamplerCustomAdvanced / LTXVSampler扩散采样
LTXDecodeVideo / VAEDecode解码输出

导入步骤

  1. ComfyUI → Load/Import Workflow
  2. 导入对应 JSON 文件
  3. 下载缺失模型 + 输入视频
  4. 运行

七、与 AI 短剧生产管线的融合评估

当前管线: Jellyfish + ComfyUI + LTX2.3

剧本(LMM) → 分镜(DeepSeek) → 角色资产(ComfyUI 出图)
→ 视频生成(Seedance API/LTX2.3) → 配音(TTS) → 剪辑导出

LTX2-ICEdit-Insight 融入点

1. 🔥 预处理阶段 (最大价值)

场景: 从多平台采集的短剧素材（抖音/快手/B站），存在水印、字幕、画质低劣

原始素材(带水印/字幕/低清)
    ↓ LTX2-ICEdit-Insight
清洁素材(无水印/无字幕/高清)
    ↓ Jellyfish 正常管线
最终成片

价值:

  • 解决”素材污染”问题，很多高播放短剧视频带了水印无法直接二创
  • 低清老视频修复后可作为 AI 短剧的 reference 素材
  • 可显著降低手动去水印/去字幕的人工成本

2. 🔥 后处理阶段

场景: AI 生成视频的最终抛光

AI 生成视频(LTX2.3/Seedance)
    ↓ LTX2-ICEdit-Insight (hd 模式)
高清成品(去伪影/增强纹理/色彩增强)

价值:

  • LTX2.3 视频生成本身可能有伪影/闪烁 → IC-Edit 可以做最终修复
  • 将低分辨率输出升级到 704×1184 高清

3. 🔥🔥 ComfyUI 深度整合 (最优路径)

场景: 与现有 ComfyUI 工作流无缝衔接

ComfyUI 工作流:
  LTXLoadVideoModel → LTXICLoRALoaderModelOnly → LTXAddVideoICLoRAGuide
  → ... (其他处理节点) → LTXDecodeVideo → 输出

价值:

  • 不需要 Insight checkpoint，直接用现有 LTX-2.3 模型
  • 可作为 ComfyUI 工作流的一个”清洗模块”
  • 与 Jellyfish 的 ComfyUI 桥接（comfyui-bridge/generate_frames.py）天然兼容

4. Jellyfish Provider 集成

场景: 将 IC-Edit 封装为 Jellyfish 的一个 Provider

融合方案价值难度硬件门槛优先级

⚠️ 约束与风险

  1. 硬件门槛高: 24GB VRAM (RTX 4090)，当前本地 RTX 3050 4GB 不可用
  2. 云端方案: Running Hub 已上，可通过 API 调用（待确认 API 可用性）
  3. 许可证不明确: README 无 License 声明，商用前需确认
  4. 通用编辑未开放: instruction-driven semantic editing 仍在训练
  5. 与 Bernini 定位不同: Bernini 做视频编辑/替换，IC-Edit 做视频修复/增强，两者互补
