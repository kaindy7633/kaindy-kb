二、架构分析

2.1 核心架构：MLLM 语义规划器 + DiT 渲染器

Bernini 的整体架构是双阶段管线：

用户简单指令 → [PromptEnhancer (MLLM)] → 增强后的电影级提示词
                                              ↓
源媒体(视频/图片) → [BerniniRendererPipeline] → 编辑后输出
                       ↑
              Wan2.2 DiT 双专家渲染器
              (high-noise / low-noise)

第一阶段：PromptEnhancer（语义规划器 / PE 节点）

本质: 一个基于 OpenAI 兼容 API 的提示词增强系统，不是本地 MLLM，而是通过云 API 调用视觉语言模型。

关键特性:

  • 默认模型: gpt-5.4-2026-03-05（OpenAI）
  • 支持通过环境变量配置：BERNINI_PE_API_KEY / BERNINI_PE_BASE_URL / BERNINI_PE_MODEL
  • 对每个 task type 有独立的中文 System Prompt 模板（详见 prompt_enhancer.py）
  • 支持视频帧提取（decord）+ base64 编码送入 VLM
  • 最多 8 次重试，带指数退避
  • 增强模板包含：电影美学（光源/色调/镜头/构图）、动作时序描述、安全审核规则

支持的 task type 及专属模板:

Task Type模板说明
t2vT2V_A14B_EN_SYS_PROMPT文生视频：添加电影美学+动作时序
t2iT2I_A14B_EN_SYS_PROMPT文生图：静态场景，不要运动描述
v2v / mv2vV2V_TEMPLATE视频编辑：Modifications + Preservations 双段结构
i2iI2I_TEMPLATE图片编辑：同 v2v 逻辑
rv2vVR2V_TEMPLATE参考图引导视频编辑：Replace/Add/Remove/Restyle
r2v / r2iR2V_TEMPLATE / R2I_TEMPLATE主体驱动生成：Short + Long instruction JSON
i2vI2V_TEMPLATE图生视频：单图/首尾帧/三帧
vi2vVI2V_TEMPLATE视频内 content propagation
ads2vADS2V_TEMPLATE广告植入

安全审核（内置于 T2V 系统提示词中）:

  • 色情内容检测 → 替换为高美感 prompt
  • 比基尼 → 确保发生在沙滩/泳池场景
  • 同性恋亲密内容 → 替换为非亲密动作

第二阶段：BerniniRendererPipeline（DiT 渲染器）

核心组件:

BerniniRendererModel
├── UMT5 Text Encoder (来自 Wan2.2 基础模型)
│   └── 将 prompt 编码为 512 维文本嵌入
└── GEN_Wanx22 (双专家 DiT 扩散解码器)
    ├── Transformer 1 (高噪声阶段, t ∈ [0.875, 1.0])
    │   └── 学习 Bernini 训练的高噪声权重
    ├── Transformer 2 (低噪声阶段, t ∈ [0, 0.875))
    │   └── 学习 Bernini 训练的低噪声权重
    └── APG 引导机制 (Adaptive Projected Guidance)
        ├── 模式: rv2v, v2v, v2v_chain, t2v, r2v_apg, v2v_apg, t2v_apg
        ├── 参数: omega_V, omega_I, omega_TI, omega_scale
        └── UniPC 调度器 (用于 _apg 模式) / FlowMatch 调度器

双专家架构原理:

  • switch_dit_boundary = 0.875：前 87.5% 的扩散步使用高噪声专家，后 12.5% 使用低噪声专家
  • 两个 transformer 共享 Wan2.2 架构，但权重通过 Bernini 微调得到
  • 这是字节 Seedance 系列的技术传承（双专家 → 视频编辑精细化）

引导模式（Guidance Modes）:

模式输入用途
t2v / t2v_apg文本文生视频
v2v / v2v_apg视频+文本视频编辑
v2v_chain视频+文本链式 APG（多条件叠加）
rv2v视频+参考图+文本参考图引导编辑
r2v_apg参考图+文本参考图驱动视频生成

APG (Adaptive Projected Guidance) 机制:

  • 来自论文 arXiv:2410.02416
  • 核心思路：将条件与无条件预测的差异投影到条件预测的正交方向
  • 带动量缓冲 (momentum=-0.5) + 范数阈值裁剪
  • 比传统 CFG 更好地保持编辑区域外的内容不变

3.2 已知局限（来自实测 + 仓库分析）

局限详情
❌ 人脸替换差参考图+视频替换衣物可，人脸效果不强
❌ 添加新物体不稳定添加第三人/物体 → 远景模糊、飘移
❌ 大规模场景改动换背景材质可，但添加大型新元素不稳定
❌ 动作迁移不行Bernini 定位是编辑不是运动生成
❌ 8 GPU 门槛视频任务需要 8 张 H100/H800
❌ 无 ComfyUI 原生集成官方仓库无 ComfyUI 节点，靠社区（TE Bernini）
❌ 无 MLLM 本地部署PromptEnhancer 依赖云端 API（OpenAI 兼容）
⚠️ 生态极早期开源仅 9 天，社区节点/教程极少
⚠️ 无 Release 管理无版本号，纯 main 分支开发

四、与 Seedance / LTX 的关系

4.1 Bernini vs Seedance

维度BerniniSeedance
定位视频编辑框架视频生成模型
核心能力编辑(换装/天气/修改)生成(文生视频/图生视频)
底层引擎Wan2.2 双专家 DiTSeedance 自研 DiT
架构UMT5 + Wan2.2自研 T5 + DiT
开源状态✅ 开源 (Apache 2.0)❌ 闭源
技术关联双专家架构、Ulysses 并行、VeOmni同属字节 Seed 团队技术栈

关系总结:

  • Bernini 和 Seedance 同属字节跳动 Seed 团队的技术产出
  • Bernini 复用了 Seedance 系的双专家 DiT、VeOmni 并行库、APG 引导等技术
  • Bernini 是字节在视频编辑方向的开源尝试，Seedance 是生成方向的闭源旗舰
  • 对短剧管线: Bernini 可承担 Seedance 生成后的后期编辑角色（换装、天气、修穿帮）

4.2 Bernini vs LTX

维度BerniniLTX-Video 2.3
定位视频编辑视频生成 (T2V/I2V)
硬件门槛8×H100（视频）12GB 显存可跑 1080p
架构DiT 双专家 + VAEDiT + VAE (轻量级)
编辑能力⭐⭐⭐⭐⭐ 强项⭐⭐ 弱项
生成长度81帧@16fps (~5s)可达 1 分钟+
开源协议Apache 2.0Apache 2.0
ComfyUI社区节点原生支持

关系总结:

  • LTX 是轻量级生成引擎，Bernini 是重量级编辑引擎
  • 互补关系：LTX 生成 + Bernini 编辑 是理想的低成本管线
  • LTX 在 ComfyUI 生态更成熟，Bernini 的 ComfyUI 集成还在早期

5.3 PromptEnhancer 独立价值

Bernini 的 PromptEnhancer 模块有独立复用价值：

  • 可提取其 System Prompt 模板，用于我们自己的提示词增强管线
  • 模板中的电影美学规则（光源/色调/镜头/构图）可用于 Seedance/LTX 生成提示词
  • 安全审核规则可作为内容合规参考

七、集成方案建议

7.1 近期（1-2 个月）：观望 + 准备

  1. 跟踪仓库发展: Watch bytedance/Bernini，关注单GPU优化、ComfyUI 官方节点
  2. 提取 PE 模板: 将 prompt_enhancer.py 中的 System Prompt 模板提取为独立资源
  3. 硬件评估: 评估是否有 8×H100 集群可用（云端 API 或自建）
  4. ComfyUI 节点测试: 在测试环境部署 ComfyUI-Bernini 社区节点

7.2 中期（3-6 个月）：有限集成

如果生态发展良好（单GPU支持、ComfyUI 稳定）：

管线方案 A: 编辑为主
  LTX2.3 生成 → Bernini 编辑（换装/天气） → FFmpeg 合成

管线方案 B: 修图辅助
  Seedance 2.0 生成 → Bernini 编辑（修穿帮/细节） → Hyperframes 剪辑

管线方案 C: PE 独立使用
  Bernini PE 模板 → 增强提示词 → 任意视频生成模型

7.3 长期：深度集成

  • 将 Bernini 编辑节点集成到 Jellyfish 平台管线中
  • 提供 REST API 封装（基于 gradio_demo.py 改造）
  • 建立编辑模板库（换装/天气/风格预设）

7.4 风险提示

风险影响缓解
硬件门槛过高无法本地部署等待单GPU优化/使用云端API
生态不成熟维护成本高先观望，不急于集成
与 Seedance 内部路线冲突字节可能弃开源保闭源关注仓库活跃度变化
视频质量不稳定编辑效果不可控需要人工审核+重试机制
