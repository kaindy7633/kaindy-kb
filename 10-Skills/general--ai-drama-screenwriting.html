AI 短剧/漫剧编剧技法

从 7 部真实商业剧本中提炼的创作规律。每集 2-3 分钟，50-60 集为一季。

剧本标准格式

第N集
场景X：地点-时间-内外
人物：角色A、角色B、角色C
△ 动作描述（纯视觉化，不用形容词，不写心理）
角色A：（情绪标注）台词
角色A OS：内心独白
【闪回】/【本集完】
【此处需要蒙版】（给剪辑师的备注）
音效：xxx
字幕：时间/地点提示

核心公式

第1集 = 强冲突 + 钩子

  • 前30秒：灭门/跳楼/被逐/车祸 — 必须是不可逆的人生巨变
  • 中间：世界设定 + 人物处境
  • 结尾：系统激活/身份互换/重生完成 → 钩子

情绪节奏：压 → 爆 → 喘（3拍循环）

  • 压 3 分钟：压抑、被欺、忍耐
  • 爆 1 分钟：反抗、打脸、逆袭
  • 喘 30秒：情感呼吸 — 内心独白 OS、闪回、空镜

打脸密度

  • 小打脸：每 2-3 集一次（怼嘴碎亲戚、压服小反派）
  • 大打脸：每 5-8 集一次（公开场合打脸核心反派、身份揭露）

情绪表达技法

OS（内心独白）的3种用法

  1. 身份揭露：角色外表在笑，OS 在恨 → 反差张力
  2. 信息补全：观众需要知道但角色不能说的
  3. 情感转折：从恨到爱、从怀疑到信任的临界点

台词写作原则

  • 每句台词推动剧情或揭示性格，不做废话
  • 情绪标注放在括号里：（冷笑）（哽咽）（低声）
  • 关键台词要短且有记忆点：“若有来生，换我来送你下地狱”
  • 反派台词要有压迫感：“你的字，和林将军太像了”

高级情感技巧（从剧本中学到）

  1. 物件情感锚：玉佩、令牌、成绩单 → 贯穿全剧的情感触发点
  2. 镜像对照：镜子里外两个自己 → 身份伪装下的真实自我
  3. 闪回切割：加蒙版/波纹/褪色 → 回忆和现实明确分界
  4. 子弹时间：关键时刻暂停，系统介入 → 玄幻/系统文的情绪高峰
  5. 正反打镜头：A看B，B看A → 无声的情绪对抗
  6. 情绪路线图（🔥 抖音 @AIGC自修室，2026-06）：AI 演员缺乏表现力 → 不是模型问题，是提示词缺少情绪弧线。关键技法：
    • 摒弃单标签情绪（“悲伤”），改用渐进式路线图（“眼眶微红→泪水打转→终于落下→低头拭去”）
    • 每镜标注：面部表情→声音变化→肢体语言→情绪弧线的渐进序列
    • 导演阐述式分镜：不只描述画面，还要给表演指导（见 references/emotional-roadmap-template.md）

女频 vs 男频差异

维度女频男频
核心驱动复仇/被爱/身份确认变强/逆袭/守护
节奏情感铺垫3-5集打怪升级每集有爽点
金手指重生记忆/系统暴击系统/修炼加速
人物关系相爱相杀/联手收小弟/开后宫
情感表达OS独白为主行动证明为主

审核红线（5/9 团队讨论确定）

  1. 跳楼/自杀 → 不直接展示，用暗示（音效+黑屏+他人反应）
  2. 血迹 → 优先避免，必须有时用暗红色
  3. “死”字 → 字幕需斟酌，不同平台尺度不同
  4. 广电新规后 → 重生/复仇/穿越题材高危，动态漫更安全
  5. 每个平台审核尺度不同 → 先传一版试水，按反馈改

成本优化嵌入创作

  1. 改编 > 原创：甲方可能只移一个剧情位置就是”版本答案”
  2. 废片率控制：台词调完后几乎不出现废片 → 比同行省 60% 算力
  3. 每集控制：2-3 分钟，场景≤3个，人物≤5个
  4. 场景复用：核心场景（青楼/严府/家中）反复出现
  5. 抽卡标记：人物设计做好后一卡到底不换人

「一卡」概念

一卡 = 一集完整剧本的卡面文档，包含：

  • 场景描述（含光线、色调、氛围关键词，可直接给 AI 出图）
  • 出场人物列表
  • 台词和动作标记
  • 每镜时长预估
  • 音效和音乐提示

甲方批注 = 在原文上标注修改方向，不改文只打批注。

分镜拆解：10镜节奏模板（来自 novel-to-drama-system）

从 boxue96/novel-to-drama-system 提取的AI分镜拆解prompt模式，每章拆为精确10镜，每镜12秒，总2分钟：

10镜节奏分配（严格遵守）：
- 镜1：开场定调。全景或中景，场景地点+人物关系+情绪基调
- 镜2-3：冲突升级。中近景，对话推进矛盾
- 镜4-7：交锋爆发。近景+特写交错，对白密集，情绪拉满
- 镜8-9：转折反杀。一个关键动作或一句台词改变局面
- 镜10：钩子收尾。中景/全景，动作型结尾，让观众必须点下一集

每镜字段：

  • visual_description: 80-150字，只描述镜头画面（空间方位/人物动作/光线/构图），零心理活动
  • dialogue_lines: 对白取自正文不得编造，每句≤25字，speaker用角色真名
  • camera_notes: 景别（全景/中景/近景/特写）+运镜方式（固定/推/拉/摇/跟）
  • prompt（视频生成用）: 150-300字 — “现代都市竖屏短剧，[场景]，[人物外观+动作]，[光线+色调]，[氛围]，电影质感”。禁止写角色真名，用外观描述替代
  • emotion: 情绪基调标签
  • duration_estimate: 统一12秒

铁律：characters只填实际出场人物，过场角色用”助理/司机”；prompt融入具体物件动作（杯子推倒/文件散落/门把手转动）

Prompt热加载系统（来自 novel-to-drama-system）

编辑 prompts/*.py 文件→下次API调用自动生效，零重启。核心机制：mtime检测缓存失效+importlib.reload。薄封装层 prompt_builder.py 只做参数转发，所有prompt逻辑在独立 .py 文件中。

借鉴价值：Jellyfish 的 shot_frame_prompt/divide/extract 可改为同样机制，编辑 prompt 无需重启服务。

分层上下文注入（三漏斗模型）

从宏观到微观的严格分层注入，每层只注入该层需要的上下文，控制token消耗：

Layer 1 分卷大纲: 故事梗概+世界观(2K字)+角色体系+故事线+已有分卷(情绪弧线防止重复)
Layer 2 章节细纲: 本卷规划(主题/核心事件/情绪弧线)+已有细纲(最近5章,防重复)+正文回顾
Layer 3 章节写作: 世界观(3K字)+角色身份速查+前情提要+近期正文回顾+本章PRD+下一章预告(防抢跑)+风格规则+口语色板

关键防抢跑机制：在prompt中注入”下一章预告”，明确列出”本章严禁出现”的内容，防止AI提前推进剧情。

口语色板系统（来自 novel-to-drama-system）

每个角色5维说话方式指纹，JSON存储，prompt自动注入。遮名可辨人：

注入prompt格式：对话遮名能辨人。宋砚：短句为主；特征：话尾带'呢'；节奏：慢半拍；口癖：啧

直接可移植到 Jellyfish：Character 模型加 speech_pattern JSON字段 + common.py build_voice_rules() 函数。

硬门禁规则引擎（双层体系）

HardRules (22字段，项目级) — 注入prompt从源头约束AI：

  • 字数范围/标题字数/禁用词/禁用词上限
  • 对话规则（禁用客气词/自然口语化要求）
  • 句式规则（禁止连续相同开头/禁止说破情绪/禁止解释性标记）
  • 描写规则（连续环境描写上限/禁止无用细节）
  • 视角规则（内心独白上限）
  • 章节起结尾规则（禁止陈腐开头/结尾）

ScanRules (7字段，全局级) — 生成后扫描检测：

  • 禁用词命中上限/真实名称黑名单/段落字数/标点规范/逻辑一致性/格式检测

full quality loop：前端UI编辑规则 → prompt注入约束AI → AI生成 → word_controller字数控制 → ai_scan.py扫描 → qc_result报告

字数控制器：CJK字数统计 + 段落边界裁剪(保留完整句子) + 兜底硬截断 + markdown清洗

写后质检引擎（来自 novel-to-drama-system ai_scan.py）

纯函数扫描引擎，输入正文+规则→输出质检报告。可在分镜/剧本生成后自动运行：

硬门禁扫描（error级别）：

  • 禁用词命中检测：超阈值报error
  • 真实名称黑名单：检测”北京/上海”等真实地名
  • 字数范围校验：低于下限或超出上限

软门禁扫描（warning级别）：

  • 陈腐开头/结尾检测
  • 说破情绪词检测（“感到/觉得”等）
  • 解释性标记检测（“这意味着/显然”等）
  • 对话客气词检测（“您/请问”等）
  • 八股文句式开头重复检测（“然而/因此”连续≥3次）
  • 连续环境描写超标检测
  • 标点多样性检测

返回格式：{status: "ok"|"warning"|"error", issues: [...], error_count, warning_count, scanned_at}

注意：该模块为纯函数，不依赖DB，可从 novel-to-drama-system 直接移植到 Jellyfish。
