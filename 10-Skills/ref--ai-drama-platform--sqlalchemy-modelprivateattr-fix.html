SQLAlchemy ModelPrivateAttr Bug — Diagnostics & Fix

记录日期: 2026-05-16 | SQLAlchemy 2.0.48 | SQLite | FastAPI

现象

batch-generate API 返回 generated=0, skipped=N，skip_reason 为：

'ModelPrivateAttr' object has no attribute 'category'

根因

在 SQLAlchemy 2.0.48 + SQLite + FastAPI async session 上下文中， session.get(Model, model_id) 返回的对象是 ModelPrivateAttr（SQLAlchemy 内部描述符）， 而非真正的 Model ORM 实例。访问 model.category、model.provider_id 等映射属性时抛出 AttributeError。

为何独立脚本正常而 API 失败：同一 venv 下用 async_session_maker() 创建的 session 在独立脚本中 工作正常（isinstance(model, Model) 为 True），但在 FastAPI Depends(get_db) 注入的 session 中 却返回 ModelPrivateAttr。可能原因：FastAPI 的事件循环/线程模型与 SQLAlchemy async engine 的 greenlet spawn 交互导致的映射注册时序问题。

诊断脚本

保存为 /tmp/debug_model.py 并在 backend venv 下运行：

运行：cd /home/kaindy/ai-drama-platform/Jellyfish/backend && .venv/bin/python3 /tmp/debug_model.py

修复方案 (已实施)

文件：app/services/llm/resolver.py

1. _resolve_model — select + raw SQL fallback

2. 新增 _get_model_category — 纯 SQL fallback

3. get_model_by_category — enum normalize

重启须知

  • uvicorn --reload 的 touch 可能不生效（文件被 reloader spawn 的子进程缓存）
  • 必须硬重启：kill <pid> → 重新 uvicorn
  • 清理 __pycache__：find . -name "resolver*.pyc" -delete

受影响的其他路径

除了 batch-generate，以下路径也调用 get_model_by_category 或 _resolve_model， 修复后全部受益：

调用方影响
resolve_image_model (image_tasks.py)图片生成任务的模型解析
build_chat_model_from_providerLLM 对话模型构造
build_default_text_llm默认文本 LLM
get_provider_by_model_or_id通过模型获取 Provider
