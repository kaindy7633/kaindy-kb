二、成本优化（Cost Optimization）

快速诊断

Cron 通常占 60-80% 总成本。

七大成本杠杆

#杠杆命令/方法预期节省
1reasoning_efforthermes config set agent.reasoning_effort low30-40% output
2max_turnshermes config set agent.max_turns 50；cron 用 2020-30%
3Model tiercron 用 deepseek-v4-flash（~3x 便宜于 v4-pro）40%/cron
4Toolsets 裁剪cron 限制为 7 核心 toolsets5-10%/turn
5Skip logic无新任务时提前退出，省 100% 空跑成本最高 100%
6Compressionhermes config set compression.threshold 0.35~10% 长会话
7删除低价值 cronshermes cron remove <job_id>100% of that job

用户偏好：优先直接删除低价值 cron，而非降频。“直接砍掉，不要它了，收益很低” 是成本决策的默认立场。

实战成果（2026-05）

¥600/mo → ¥30-50/mo（~92% 削减）：

  • reasoning_effort=low, max_turns=50
  • 2 crons removed, 2 crons on v4-flash, 1 cron paused
  • Toolsets trim 50+→7, skip logic, compression 0.35
  • Final: 2 agent-driven crons daily (both v4-flash), 3 script-only ($0)

Hermes API Key 脱敏拦截 🆕 — 当尝试通过 terminal/execute_code 写入含 API Key 的命令时，Hermes 会自动脱敏并可能破坏语法：

  • 症状：sed -i 's/^KEY=*** → 语法错误 / .env` 写入静默失败
  • 变通：将 Key 写入临时文件 → 脚本从文件读取 → 操作目标
  • 脱敏范围：terminal、write_file、execute_code、heredoc 全覆盖
  • 终极方案：用户手动在 terminal 跑含 Key 的命令

逆向迁移：EC2 → 本地

  1. 拉取最终备份：从 EC2 scp 最新备份到本地
  2. 还原：按上文”备份还原”步骤恢复
  3. 更新 Hermes：uv pip install --upgrade hermes-agent
  4. 重建 Gateway：hermes gateway install && hermes gateway start
  5. 退役 EC2：⚠️ 先删除 Auto Scaling Group，再终止实例 — 否则 ASG 会自愈出新实例，产生重复 cron 和数据混乱
  6. 清理 Memory：删除 EC2 相关的 memory entries

WSL 用户额外检查项见 references/wsl-migration-checklist.md。

SSH 排障（macOS）

Connection closed by remote host port 22 的排查顺序：

  1. VPN/代理干扰（macOS 最常见）— Shadowrocket/ClashX/Surge TUN 模式劫持所有流量。关闭代理重试。
  2. Key 文件权限 — macOS GUI 下载可能设 owner 为 root。sudo chown $USER ~/.ssh/key.pem && chmod 600 ~/.ssh/key.pem
  3. Key 格式验证 — head -1 ~/.ssh/key.pem 必须是 BEGIN OPENSSH/RSA PRIVATE KEY
  4. Key 与实例不匹配 — 比对 AWS Console 的 Key pair name。不匹配则重建实例更快。
  5. 始终加 IdentitiesOnly — ssh -o IdentitiesOnly=yes -i ~/.ssh/key.pem ubuntu@<ip>
