GitHub Authentication Setup

This skill sets up authentication so the agent can work with GitHub repositories, PRs, issues, and CI. It covers two paths:

  • git (always available) — uses HTTPS personal access tokens or SSH keys
  • gh CLI (if installed) — richer GitHub API access with a simpler auth flow

Detection Flow

When a user asks you to work with GitHub, run this check first:

Decision tree:

  1. If gh auth status shows authenticated → you’re good, use gh for everything
  2. If gh is installed but not authenticated → use “gh auth” method below
  3. If gh is not installed → use “git-only” method below (no sudo needed)

Method 1: Git-Only Authentication (No gh, No sudo)

This works on any machine with git installed. No root access needed.

Option A: HTTPS with Personal Access Token (Recommended)

This is the most portable method — works everywhere, no SSH config needed.

Step 1: Create a personal access token

Tell the user to go to: https://github.com/settings/tokens

  • Click “Generate new token (classic)”
  • Give it a name like “hermes-agent”
  • Select scopes:
    • repo (full repository access — read, write, push, PRs)
    • workflow (trigger and manage GitHub Actions)
    • read:org (if working with organization repos)
  • Set expiration (90 days is a good default)
  • Copy the token — it won’t be shown again

Fine-Grained PAT Caveat (IMPORTANT)

Fine-grained personal access tokens (github_pat_...) consistently fail with git HTTPS push (403) even when the token’s API permissions show push: true, admin: true. The API layer and git protocol layer use different auth paths — a token that passes curl -H "Authorization: Bearer $TOKEN" API checks can still be rejected by git push.

Simplest fix: use a Classic PAT (ghp_..., 40 chars). Store it in ~/.hermes/.env as GITHUB_TOKEN=ghp_... and use directly in git URLs:

Classic PATs reliably work for both API and git operations. No workarounds needed.

Fallback order when pushing:

  1. Classic PAT (ghp_...) from ~/.hermes/.env — most reliable, simplest
  2. Fine-grained PAT (github_pat_...) via GIT_ASKPASS — often fails, don’t spend too long on it
  3. GitHub Git Database API (create blobs/trees/commits via REST) — 100% reliable but complex

GIT_ASKPASS Pattern (Headless Git Auth)

When you need to authenticate git without interactive prompts (e.g., inside Hermes), use GIT_ASKPASS to provide credentials from a file:

Token type matters for askpass:

  • Classic PAT: username can be anything, password = token
  • Fine-grained PAT: username = x-access-token (or token itself), password = token (or empty)

Troubleshooting

ProblemSolution
git push asks for passwordGitHub disabled password auth. Use a personal access token as the password, or switch to SSH
remote: Permission to X deniedToken may lack repo scope — regenerate with correct scopes
403 with fine-grained PAT despite API showing push: trueKnown issue — fine-grained PATs may not work for git HTTPS. Use Git Database API fallback (see github-repo-management references/git-database-push.md)
fatal: Authentication failedCached credentials may be stale — run git credential reject then re-authenticate
ssh: connect to host github.com port 22: Connection refusedTry SSH over HTTPS port: add Host github.com with Port 443 and Hostname ssh.github.com to ~/.ssh/config
Credentials not persistingCheck git config --global credential.helper — must be store or cache
Multiple GitHub accountsUse SSH with different keys per host alias in ~/.ssh/config, or per-repo credential URLs
gh: command not found + no sudoUse git-only Method 1 above — no installation needed
Token gets truncated by Hermes toolsSplit into chunks and concatenate via Python; use GIT_ASKPASS to avoid embedding in shell commands
