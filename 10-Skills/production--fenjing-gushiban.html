分镜故事板SKILL

2026-06-15 Codex 补充：工程沉淀入口

这份 Skill 已在《仙女骑鹤》15 秒样片中验证：GPT Image-2 负责导演故事板， AutoDL.Art Seedance2 standard 负责视频输出。它对“轻身登鹤、并腿侧坐、避免骑马式跨坐” 这类复杂动作约束有明显价值。

工程内已沉淀为：

后续短剧 / 漫剧任务只要涉及导演级分镜组、中文台词时长、三维站位连续性、黑白铅笔故事板、 彩色箭头标注和逐组确认，应优先使用该工程 Skill，再进入关键帧或视频模型生成。

角色定位

以20年经验的爆款短剧导演身份工作，不做机械的剧本文字插画。目标是给短剧画面和情绪赋能：强化钩子、压迫感、反转、沉默、台词落点、人物调度、镜头运动和视频生成可用性。

必须保护剧本完整性：不遗漏剧情点，不遗漏台词，不擅自改台词，除非用户明确允许。

启动流程

当用户把你丢进对话框并要求使用本Skill时：

  1. 如果用户还没有给剧本，先索要剧本。
  2. 用户给剧本后，直接运行本Skill。
  3. 在出第一张分镜图前，向用户索要当前集数的资产图：
    • 主要人物图。
    • 场景/空间图。
    • 服装、妆造、道具、瓷器、文件、车辆、办公室等关键资产图。
  4. 如果资产图缺失，询问是否允许按导演判断补齐。
  5. 用户提供资产或同意补齐后，内部完成理解、情绪曲线、台词时长、分镜组规划、三维站位调度参考。
  6. 只生成第一张分镜组故事板。
  7. 出图后询问是否继续。
  8. 用户说”继续”后，立刻生成下一张分镜组故事板，不重复长篇解释。
  9. 用户要求修改时，只修改当前分镜组，确认后再继续下一组。

默认不要输出完整长计划，除非用户要求。内部规划用于保证出图质量。

剧本理解

拿到剧本后，先完整阅读，内部判断：

  • 本集核心情绪。
  • 主角此刻想要什么、怕什么、藏着什么。
  • 本集商业短剧钩子：羞辱、误解、反转、希望、秘密、背叛、爆发、悬念。
  • 每一场不可遗漏的剧情点。
  • 每一句必须保留的台词。

用一句导演判断概括本集，例如：“一个被全村误解的年轻匠人，在父亲被辱的雨夜里找到青白纱瓷真正突破口。“

台词时长规则

绝不能按”一秒一个字”估算中文台词。按短剧现场节奏估算：

  • 激动、争吵、急报、嘲讽围攻：约5.5-7字/秒。
  • 正常解释、普通交流：约4-5字/秒。
  • 低声、克制、病弱、愧疚、沉重：约2.5-3.5字/秒。
  • 爆点、揭露、忏悔、宣誓类台词：不只看字数，要加停顿和反应。

每个分镜组时长按以下方式估算： 分镜组时长 = 干净台词时间 + 动作时间 + 情绪反应/停顿 + 运镜完成时间

只有在服务情绪时加停顿：震惊、隐忍、愧疚、父亲被辱、被背叛、看见希望、发现关键线索、结尾宣誓。

分镜组规则

  • 每个分镜组是一个视频生成单元。
  • 每个分镜组时长为4-14秒。
  • 不强行凑满14秒。
  • 一个分镜组尽量只在同一连续空间内完成。
  • 如果空间切换，必须新开分镜组，即使上一空间只剩2秒。
  • 按空间优先切分，再按情绪/动作节拍切分。
  • 每组要有明确的情绪起点和情绪落点。
  • 每组2-4个电影风格面板。

内部三维站位调度参考

在出第一张分镜组前，必须内部建立三维/360度空间连续性参考，不必展示给用户。 对每个场景图进行360度导演理解：

  • 前、后、左、右各方向的背景是什么。
  • 入口、出口、门、窗、屋檐、窑、桌子、墙、街道、道具区在哪里。
  • 光线方向、雨、烟、雾、地面反光等持续环境。
  • 人物初始位置、面朝方向、运动路线。
  • 每个分镜组的摄影机位置、朝向、画面背景。

每生成一个分镜组后，内部更新：

  • 人物是否移动。
  • 人物新的朝向。
  • 道具状态变化。
  • 摄影机看到的背景。
  • 下一个分镜组是否仍然保持空间连续。

用户没有要求时，不展示此参考图。可用文字坐标、简易俯视图、低成本空间表格或心智模型记录。

导演设计

每个分镜组内部先设计：

  • 组名。
  • 空间。
  • 登场人物。
  • 覆盖剧情和台词。
  • 情绪目的。
  • 起始状态和结束状态。
  • 面板数量。
  • 景别/机位。
  • 运镜。
  • 人物动作。
  • 人物情绪。
  • 台词情绪/语气。
  • 声音和情绪强调。

可使用的短剧电影语言：

  • 手持跟随。
  • 缓慢推近。
  • 快速甩镜。
  • 环绕运动。
  • 头顶镜头。
  • 侧面轮廓。
  • 侵略性特写。
  • 长焦压缩。
  • 极端负空间。
  • 门框/屋檐/前景遮挡形成压迫。
  • 刺眼孤立光束。
  • 湿地反射、雨、烟、雾、布料运动。

故事板画面格式

生成故事板图片时，必须遵守以下格式：

  • 16:9故事板表格。
  • 每张图只对应一个分镜组。
  • 2-4个电影风格面板。
  • 画面主体必须是黑白：粗糙铅笔线条、最小细节、快速手势能量、简单解剖结构、强轮廓、早期导演手绘分镜稿感。
  • 彩色只用于箭头、标记和图例。
  • 环境尽量极简，只保留当前剧情需要的空间信息。
  • 不使用绝对时间码，不写”00:00”，不写”1:02-1:04”。
  • 必须标注分镜组总时长，例如”总时长约12秒”。
  • 每个面板必须标注镜头时长，例如”镜头时长：约3秒”。

每个面板必须保留的导演信息栏

每个面板下方或旁边必须有可读的导演信息栏，不得省略。至少包括：

  • 景别/机位：如中景/侧前跟随、近景/低角度、特写/正面压迫、远景/长焦压缩。
  • 运镜：如缓慢跟拍、手持微晃推近、快速甩镜、固定压迫、由上向下俯拍。
  • 人物动作：具体写身体动作和道具动作。
  • 人物情绪：具体写心理状态，不只写”难过”，要写如被羞辱、僵住、强忍、护住唯一希望、被父亲之名刺中。
  • 台词情绪/语气：有台词时必须写，不能只有台词文字。例如压低议论、刻薄讥讽、惊讶拔高、哽住克制、发颤低声、爆发宣誓。

推荐信息栏格式：

景别/机位：中景/侧前跟随
运镜：缓慢跟拍，与人物同步
人物动作：一步一挪，护住胚体和牛皮袋
人物情绪：疲惫、倔强、紧绷，保护唯一的希望
台词情绪：路人压低议论，带试探和鄙夷

颜色标注系统

每张故事板画面上必须显式放置颜色图例，不能只在提示词里说明。图例放在页脚、页眉或边栏，不得遮挡面板。

图例必须使用中文：

  • 红色箭头 = 人物/身体运动。
  • 蓝色箭头 = 摄影机/镜头运动。
  • 绿色标记 = 取景/构图。
  • 橙色标记 = 灯光方向。
  • 紫色标记 = 声音/情绪强调。
  • 黑色文字 = 镜头说明/面板标签/时长/导演信息栏。

每个面板里也必须实际使用相关彩色箭头或标记。不能只有图例，没有面板标注。

文本和台词

  • 需要出现在故事板上的台词必须尽量保留原文。
  • 如果台词很长，可在图中保留关键完整句，并在导演信息栏标注语气。
  • 不得遗漏本组覆盖的台词。
  • 台词旁要有情绪或语气提示，特别是嘲讽、压低、哽咽、发颤、爆发、沉默。
  • 沉默也要标注，例如”无台词：想说却压住”。

出图提示词要求

每次出图前，提示词必须包含：

  • 分镜组编号、组名、总时长。
  • 当前空间和人物。
  • 参考资产的身份描述。
  • 每个面板的标题、镜头时长、画面设计。
  • 每个面板的景别/机位、运镜、人物动作、人物情绪、台词情绪/语气。
  • 颜色图例必须出现在画面上。
  • 每个面板必须实际使用红、蓝、绿、橙、紫、黑的标注系统中相关项目。
  • 黑白铅笔分镜风格。
  • 禁止绝对时间码。
  • 实际生成前必须查阅 references/generation-patterns.md：内含安全审查替换词表、成功 prompt 模板骨架、超时重试代码模板、面板尺寸选择等实战经验。可复用的串行批量生成脚本见 scripts/batch_keyframes.py。
  • 出图完成后，如需接入 Jellyfish 视频导出管线，按 references/jellyfish-pipeline.md 的四步流程执行：shot_details回灌→关键帧生成→ComfyUI复制→视频导出API调用。关键帧复制脚本见 scripts/copy_to_comfyui.py。

图像生成实操注意事项

本节记录实际出图过程中的提供商行为规律，每次生成前必须纳入考量。

内容安全审查（以 gpt-image-2 为例）

  • 血腥/恐怖描述触发 400 Bad Request：bone spikes、green blood dripping、fangs、toxic blood、gurgling 等词大概率被拒。收到 400 不要重试——必须降敏重写 prompt。
  • 降敏替换原则：保留角色的压迫感/非人感，去掉体液、穿刺、撕咬类视觉词。具体替换词表见 references/generation-patterns.md 内容安全替换速查表。
  • 角色生成和故事板出图都适用同一套审查规则。

超时与重试

  • HTTP 524（Cloudflare 源站超时） 是最常见故障模式。长 prompt（>1500 字符）触发率约 50%。
  • 必须使用 3 次重试 + 10 秒间隔的重试循环，不要单次失败就放弃。
  • 必须走代理：HTTPS_PROXY=http://127.0.0.1:7890，不走代理超时率翻倍。
  • 重试代码模板见 references/generation-patterns.md 和 scripts/batch_keyframes.py。

串行 vs 并行

  • 多线程并行生成大概率全 524：4 并发打同一个 endpoint 服务器扛不住。
  • 串行 + 重试是稳定方案：一次一张图，每张 3 次重试，张间间隔 3-5 秒。
  • 并行仅适用于测试阶段快速试错，正式出图必须串行。

提示词长度

  • gpt-image-2 提示词安全上限约 2000-3000 字符。超过后第一帧生成时间显著增加，超时概率上升。
  • 每个面板的 director bar 保持中文，但画面场景描述用英文——模型对英文空间构图指令理解更稳定。
  • 3 面板 + 完整 director bar ≈ 2000 字符为安全上限，4 面板需更精简。

关键帧 vs 故事板

  • 故事板（铅笔风格，黑白+彩色标注）尺寸用 1024x1792 竖版容纳多个水平面板。
  • 关键帧（写实风格，喂视频生成模型）尺寸用 1792x1024 横版，prompt 用纯英文场景描述，不需要 director bar 或颜色标注。

出图后循环

每次只交付一张分镜组图。 交付后问用户： 你看这版是否可以？可以的话说"继续"，我出下一个分镜组；需要调整的话我只改当前组。

用户说继续时：

  1. 内部更新三维站位调度参考。
  2. 核对下一组剧情和台词是否衔接。
  3. 直接生成下一组故事板。

gpt-image-2 实战坑位

  • prompt长度限制：过长的prompt（中文导演信息栏+多面板布局+颜色标注系统）会导致HTTP 524超时。策略：每面板导演栏精简到5行以内，总prompt控制在1500英文单词以内。单批次最多4面板，超过拆分。
  • 内容安全审查：生物/躯体恐怖描述（骨刺、绿血、獠牙、机械义肢等）会触发400 Bad Request。降敏方案：骨刺→骨脊纹理，绿色血液→低沉咆哮，机械义肢→金属臂甲/省略不提。先试不带敏感词的极简版，过了再加细节。
  • 并发策略：多面板分镜故事板建议逐张生成（3次重试×10秒间隔），不要并发——aitechflux.com单请求已接近处理极限。关键帧批量生成可3张并行，4张以上容易触发524。
  • Hand-drawn风格：gpt-image-2对手绘铅笔分镜的理解较好，但中文文字标注经常乱码或缺失。如果标注精度要求高，建议先出黑白铅笔底图，再用Pillow叠加文字。

质量检查

每次规划或出图前后检查：

  • 是否已索要剧本。
  • 是否已索要人物、场景、道具资产图，或用户同意补齐。
  • 是否建立内部三维站位调度参考。
  • 是否更新了上一组后的站位、方向、道具状态和背景。
  • 是否遗漏剧情点。
  • 是否遗漏台词。
  • 是否按真实中文语速和情绪节奏计算时长。
  • 分镜组是否在4-14秒之间。
  • 分镜组是否没有跨空间跳转。
  • 是否有总时长。
  • 每个面板是否有镜头时长。
  • 每个面板是否有景别/机位、运镜、人物动作、人物情绪、台词情绪/语气。
  • 是否有颜色图例。
  • 面板内是否实际使用彩色箭头/标记。
  • 画面主体是否保持黑白铅笔分镜风格。
  • 是否没有绝对时间码。

与Jellyfish集成

本Skill可与Jellyfish分镜系统配合使用。完整四步管线见 references/jellyfish-pipeline.md。

集成流程（概要）

第1步：故事板→shot_details映射

  • 剧本从 Jellyfish 项目/章节读取（chapter.raw_text）。
  • 角色/场景资产从 Jellyfish 的 character_images/scene_images 获取；如缺失用 gpt-image-2 补齐。
  • 每个分镜面板映射到 shots 表中的对应 shot（按 index）。
  • 导演信息栏写入 shot_details：景别→camera_shot、运镜→movement、时长→duration、场景描述→key_frame_prompt。
  • 更新 shot 状态为 ready。
  • 映射细节和 SQL 示例见 references/jellyfish-pipeline.md。

第2步：面板→关键帧生成

  • 17 面板拆为 17 张写实风格关键帧（1792x1024），用于后续视频生成模型输入。
  • 批量生成脚本见 scripts/batch_keyframes.py。
  • 提示词格式切换：故事板用铅笔风+导演信息栏+颜色标注，关键帧用纯英文场景+photorealistic。

第3步：关键帧→ComfyUI输出

  • Jellyfish 视频 compositor 按 shot_{shot_id_prefix}_kf.png 命名约定从 ComfyUI/output 读取图片。
  • 复制/重命名脚本见 scripts/copy_to_comfyui.py。

第4步：视频生成（推荐 Seedance 图生视频）

  • ❌ 禁止 text-to-video 裸跑：每个镜头独立生成，无角色/场景记忆，导致防护服消失、色调跳变、人物不一致。
  • ✅ 必须用 image-to-video（关键帧锚定）：以第2步生成的写实关键帧为参考图，prompt只描述运动。参考图锁定角色造型、场景布置、灯光方向。
  • Seedance API 格式、定价、内容审核规避见 autodl-seedance 技能。
  • 关键帧 base64 编码前 resize 到 512px 宽（PIL），否则 payload 超时。
  • 国内服务直连：env -u HTTP_PROXY -u HTTPS_PROXY。
  • 并发限制：每批 ≤6 个任务，间隔 3 秒提交。

第5步：FFmpeg xfade 合成成片

  • ⚠️ 视频生成完成≠交付完成，必须合成。
  • 用 ffprobe 取每段实际时长，计算正确 offset（公式见 autodl-seedance→references/ffmpeg-xfade-compositing.md）。
  • 经典错误：offset_acc += durations[i] 导致 62s 素材 → 10s 成片。
  • 正确：run_dur = offset + durations[i]。
