Douyin Video Digest

Extract knowledge from Douyin (抖音) videos AND 图文 posts when the user shares a link. Covers the full pipeline: browser-based URL extraction → download → whisper transcription → structured knowledge note.

Trigger Conditions

  • User shares a v.douyin.com or douyin.com/video/ or douyin.com/note/ link
  • User asks to extract/summarize/digest a Douyin video or 图文 post
  • User wants to learn from Chinese short-video platform content
  • User asks about Douyin monetization, AI video side-hustle, or Douyin revenue models → also load references/douyin-monetization-guide.md

When NOT to Use

  • YouTube videos → use youtube-content skill (has built-in transcript API)
  • Videos already downloaded locally → skip Phase 1-2, go straight to transcription

图文帖子处理 🆕

当用户分享的是 Douyin 图文帖（非视频）时，流程简化：

  1. Phase 1a: browser_navigate(url) — 提取标题、作者、标签、幻灯片数量（如 “1/8”）
  2. Phase 1b: browser_get_images() — 提取所有 3840×2160 内容图片
  3. Phase 2替代: 按唯一 URL 去重后用 curl 下载各幻灯片 .webp
  4. Phase 3替代: 用 Claude Code vision 分批分析（每批 ≤3 张，避免 aicodestudy.com 400）
  5. Phase 4: 同视频，结构化笔记

关键差异：

  • 无音频/转写阶段（图文无音频）
  • 图片分析用 Claude Code print mode，非 Whisper
  • 幻灯片按编号顺序（slide_01~slide_N）组织笔记

Phase 1: Browser Extraction

Why browser, not yt-dlp: Douyin requires fresh cookies even for public content. yt-dlp’s Douyin extractor fails with “Fresh cookies are needed.” Browser bypasses this.

  1. Navigate to the share link: browser_navigate("https://v.douyin.com/XXXXX/") — it auto-redirects to the full douyin.com/video/ page
  2. Extract metadata from page snapshot: title, description, author, hashtags, like/comment/share counts, chapter count, duration
  3. Get direct video URL via browser_console: Returns a CDN URL like https://v26-web.douyinvod.com/.../video/tos/.../?a=6383&...
  4. Capture chapter info (if available) from the “章节要点” panel

Pitfall: The video URL has a limited lifetime (~hours). Download immediately after extraction.

3b. Whisper Transcription

  • small model: good accuracy for Chinese, ~1GB VRAM, ~3-5 min for 15-min video
  • medium model: better accuracy, slower
  • For very long videos (>30 min): use --model tiny first pass, then redo key segments with small

Pitfall: Whisper loads the model on first run (~2GB download). Run in background with notify_on_complete=true for long transcriptions.

3c. Keyframe Extraction

Adjust fps=1/60 for density: 1/30 = every 30s, 1/120 = every 2 min.

3d. Vision Analysis (via Claude Code)

DeepSeek v4-pro is text-only and cannot analyze images. Use Claude Code print mode (see claude-code skill) for frame analysis. Claude models (sonnet-4-6, opus-4-8) have native vision and can read image files directly via the Read tool.

Batch approach (recommended for >3 frames):

Use the batch_frame_analyzer.py script from this skill’s scripts/ directory to auto-split frames into batches of 3, call Claude Code, and aggregate results into analysis_result.md.

Platform Notes

  • Douyin web player is muted by default in browsers. Audio is extracted from the downloaded mp4, not from browser playback — this is not a problem.
  • Video CDN URLs expire within hours. Don’t store the URL, always extract fresh from browser.
  • Anti-bot: Douyin’s web version is less aggressive than the app. Browser-based access with standard User-Agent works reliably for public videos.
  • Login wall: Some videos require login. If browser_navigate shows a login prompt instead of the video page, tell the user — this pipeline only works for publicly accessible videos.

Common Pitfalls

  1. Video CDN URL expires — the direct .mp4 link from Phase 1 is only valid for hours. Download immediately, don’t save for later.

  2. Whisper model download — first run downloads ~2GB model. Run in background with notify_on_complete=true so it doesn’t block.

  3. Claude Code proxy 400 errors — transit services reject >3 frames per call. Use the batch script (auto-retries with smaller chunks). Never try 4+ frames in one Claude Code call.

  4. ANTHROPIC env vars not sourced — the batch script reads ANTHROPIC_AUTH_TOKEN and ANTHROPIC_BASE_URL from the environment, but background processes and cron sessions don’t inherit .env exports. Before running batch_frame_analyzer.py, explicitly source the env file:\n bash\n source <(grep ANTHROPIC ~/.hermes/.env) # the env file exports the vars\n env | grep ANTHROPIC # verify they're set\n python3 ~/.hermes/skills/media/douyin-video-digest/scripts/batch_frame_analyzer.py /tmp/frames/\n \n If all frames return [Error analyzing ...], the token is either unset or expired.\n5. Login wall on Douyin — some videos require login to view. If browser shows a login prompt, tell the user — publicly accessible videos only.\n6. DeepSeek cannot do vision — don’t try vision_analyze with DeepSeek v4-pro, it returns 400. Use Claude Code (Phase 3d) or a configured Gemini/OpenAI provider.

  5. Large videos (>100MB) — increase curl --max-time and use fps=1/120 for sparser keyframes. Whisper small model may struggle with >30 min audio; use medium or segment first.

  6. ffmpeg scene detection vs interval — fps=1/60 (every 60s) is simple but may miss rapid scene changes. For tutorial/screencast videos, interval-based is usually fine. For cinematic content, use -vf "select='gt(scene,0.4)'" instead.

  7. 图文帖子幻灯片重复 URL (2026-06-15 发现): browser_get_images() 对图文帖返回的每张幻灯片会重复出现（每个唯一图片出现 2 次，分别在普通渲染和 2x 渲染中）。必须按唯一 URL ID 去重后再下载。去重方法：提取 URL 中的 hash 段（如 tos-cn-i-dy/<hash>~tplv-dy-aweme-images），仅保留每个 hash 的第一次出现。下载后的幻灯片命名 slide_01~slide_N.webp，按页面显示的 “1/N” 顺序组织。

  8. B站 search API 需 Cookie 头（2026-06-03 发现）。 yt-dlp 下载 B站视频时 UA+Referer 就够了，但 B站搜索 API (api.bilibili.com/x/web-interface/search/type) 会额外返回 HTTP 412 Precondition Failed，需要 Cookie: buvid3=...; _uuid=... 才能通过。用 Python urllib.request + Cookie header 可绕过；避免 curl | python3 管道（会被安全扫描器拦截）。

Verification Checklist

  • browser_navigate successfully opened the video page (not a login wall)
  • Video URL extracted and downloaded without truncation (check ffprobe duration matches page)
  • Whisper transcript exists at /tmp/douyin-audio.txt with non-empty Chinese content
  • Keyframes extracted to /tmp/frames/ (count matches expected: duration/interval)
  • batch_frame_analyzer.py ran all batches without errors → /tmp/frames/analysis_result.md exists
  • Structured note saved to ~/Documents/ai-video-research/ with title, metadata, and sections
  • Cleanup: original video + audio files deleted (keep transcript + frames only if needed)
