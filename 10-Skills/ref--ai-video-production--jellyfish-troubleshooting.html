Jellyfish 开发环境排障实录 (2026-05-08)

Problem 1: Celery 任务持续 401（API Key 双源不一致）

症状

  • POST /script-processing/divide-async 返回 task_id，Celery 秒失败
  • DB 中 generation_tasks.error: Error code: 401 - Authentication Fails, Your api key: ****2ac9 is invalid
  • 直接用 curl / httpx / ChatOpenAI 测试相同 key → 200 OK
  • 同步端点 /script-processing/divide 同样 401

排查过程

  1. 测试 key 有效性：urllib → DeepSeek /v1/chat/completions → 200 OK ✓
  2. 测试 extra_body: {enable_thinking: false} → 200 OK ✓（排除参数问题）
  3. 测试 httpx.Client(proxy=None) → 200 OK ✓（排除代理问题）
  4. 测试 langchain_openai.ChatOpenAI from venv → 200 OK ✓
  5. 对比 DB 和 .env 的 key：
  1. 对比字符级别差异：两个 key 前 10 字符相同，后面完全不同

根因

Jellyfish 从 providers 表的 api_key 列读取 key（不是从 .env 读取）。.env 的 key 在某个时刻被更换过，但 DB 中 provider 记录的 key 未同步更新。Celery worker 和 uvicorn 均从 DB 读 key，因此都 401。

修复

无需重启，下次请求自动生效。

Problem 2: Celery Worker 启动无输出（WSL 环境）

症状

  • uv run celery ... worker 启动后无任何 stdout/stderr
  • 进程存在（pgrep -f celery 有 PID）但完全静默
  • 持续 60-90s 后才出现 celery@hostname ready
  • --pool=prefork（默认）在 WSL 下特别慢

解决

  • 使用 --pool=solo 避免 prefork 子进程问题
  • 耐心等待（不要以无输出判断启动失败）
  • 验证：pgrep -af celery 应看到 worker 进程

Problem 6: 视频生成任务 401 Unauthorized（火山引擎 API Key 无效）

症状

  • POST /api/v1/film/tasks/video 返回 201，task 创建成功
  • Celery 派发后 task 秒失败（~900ms elapsed）
  • GET /api/v1/film/tasks/{task_id}/result 返回： \"error\": \"Client error '401 Unauthorized' for url 'https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks'\"

与 LLM 401 的区别

维度LLM Provider 401视频 Provider 401
Provider IDds-openai (OpenAI 兼容)c47fc9a6-... (火山引擎 UUID)
API 路径/v1/chat/completions/api/v3/contents/generations/tasks
诊断端点/script-processing/divide 直接报错/film/tasks/{id}/result 异步返回 error
Key 获取方式providers.api_keyproviders.api_key + api_secret

修复

Volcengine API Key 格式直接验证

在更新 DB 之前，可直接 curl 火山引擎 ARK API 验证 Key 有效性：

响应HTTP含义

{"error":{"message":"Invalid API key"}}401Key 格式正确但已过期/无效

Problem 7: Chapter POST 返回 500 Internal Server Error

症状

  • POST /api/v1/studio/chapters 返回 500 Internal Server Error
  • 其他 CRUD 端点（GET、PATCH）正常
  • Server 端无明显错误日志

根因

SQLite 异步驱动在高并发或特定 DB 状态下创建记录时偶发崩溃。具体原因可能是事务冲突、WAL 模式锁、或 DB 文件权限问题。
